## What the successful call proves

The call proves that Codex can traverse the installed MCP routing path:

```text
Codex host
  -> MCP server discovery
  -> tools/list
  -> tools/call
  -> Orchestra exact-command transport view
  -> RuntimeExecutor.execute
  -> trusted binding / authority / governance / lifecycle path
  -> specialist route selection
  -> ExecutionResult.output
```

The current MCP transport returns `ExecutionResult.output` from `orchestra_runtime/mcp_transport.py`. The default MCP runtime factory builds a `RuntimeExecutor` without a host-native specialist execution engine. `RuntimeExecutor._default_operation` therefore completes the deterministic orchestration path and returns the route-oriented output generated by the current runtime.

This matches current repository architecture and tests:

- `orchestra_runtime/mcp_transport.py` — `tools/call` invokes `RuntimeExecutor.execute` and returns `ExecutionResult.output`.
- `orchestra_runtime/services.py` — `_default_operation` returns `EXECUTION_COMPLETED` with the runtime's route-oriented output.
- `docs/project/OOP_RUNTIME_ARCHITECTURE.md` — runtime execution currently returns orchestration decisions rather than full host-native execution side effects.
- `tests/runtime/test_mcp_transport.py` — MCP tool-call coverage asserts command/specialist routing output, not substantive specialist findings.
- `commands/scribe.md` — Scribe behavior exists as host/agent instructions, not as a Python specialist engine invoked by the default MCP factory.

Therefore the observed response:

```text
codex adapter routed 'review-docs' to 'scribe' with governance status NOT_REQUIRED
```

is expected for the current repository version. It does not mean Scribe performed a substantive README audit.

## Compatibility incident and root cause

The original Codex startup failure was:

```text
Request _meta is required
```

That indicated Codex had selected its legacy MCP lifecycle instead of Orchestra's modern stateless `2026-07-28` contract. Both host opt-ins above are required; adding a legacy `initialize` bridge or weakening Orchestra `_meta` validation is not the correct remedy.

After both Codex opt-ins were enabled, the failure changed to an initialized-result deserialization error involving `CallToolResult`. That change confirmed Codex had entered the modern MCP path. The remaining discovery-shape incompatibility was traced to Orchestra's `server/discover` result missing Codex-compatible cache fields.

The bounded runtime fix added:

```json
{
  "ttlMs": 0,
  "cacheScope": "private"
}
```

These fields satisfy the modern discovery result shape while disabling reusable discovery caching. They are transport metadata and grant no authority.
