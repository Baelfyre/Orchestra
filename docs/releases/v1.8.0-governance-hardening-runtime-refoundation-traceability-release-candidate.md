# Orchestra v1.8.0: Governance Hardening, Runtime Refoundation & Traceability

## Release summary

Orchestra v1.8.0 strengthens the framework's governance and architecture foundations for larger, longer-lived AI-assisted software projects.

The release adds explicit architecture-governance contracts, proportional capacity and complexity reasoning, stronger evidence freshness and specialist re-entry rules, tenant-security governance, documentation traceability, runtime architecture boundaries, and expanded deterministic validation.

It also includes the validated AR-0/AR-1/AR-2 runtime architecture foundation, Scribe's documentation and traceability upgrade, bounded UI reference intelligence, Registry O7 integration, and continued specialist/provider execution work while preserving Orchestra's core authority model.

The central v1.8.0 theme is not "more automation at any cost." It is more useful autonomy with clearer ownership, proportional governance, current evidence, and explicit human authority.

Primary invariant:
```text
CAPABILITY != AUTHORITY
ROUTING != AUTHORITY
VALIDATION_SUCCESS != AUTHORITY
MERGEABLE != MERGE_AUTHORITY
```

## Highlights

### Governance hardening

Orchestra reinforces its core Prime Directive and Governed Execution Lifecycle V2. New capabilities must demonstrate an Orchestra-owned problem and proportional benefit before permanent promotion:
- **Explicit Authority Separation**: Platform capability, routing, and validation success do not confer execution or mutation authority.
- **Fail-Closed Progression**: Missing, stale, or contradictory evidence blocks transition across governed lifecycle gates.
- **Human Decision Envelope**: Autonomous progression remains strictly constrained within human-authorized execution envelopes.

### Architecture governance contracts

The framework formalizes seven machine-readable contracts spanning the entire architecture lifecycle:
- `CapacityEnvelope`: Machine-verifiable compute, storage, memory, and throughput ceilings with adaptive capacity elicitation (`UNKNOWN` is recognized as a valid first-class state).
- `ProductIntentContract`: Distinguishes underlying product problems from proposed implementation mechanisms.
- `ArchitectureComplexityDecision`: Explicit complexity budget enforcement, simpler-alternative analysis, and separation of `SCALE_READY` from `SCALE_PROVISIONED` (`FUTURE_SCALABILITY_ALONE_IS_NOT_SUFFICIENT_JUSTIFICATION`).
- `MigrationRiskContract`: Engine-aware data migration planning, locking analysis, rollback safety, and backfill risk classification.
- `ArchitectureGovernanceIntake`: Canonical intake routing with standardized change materiality levels (`TRIVIAL`, `STANDARD`, `ARCHITECTURAL`, `PRODUCTION_CRITICAL`).
- `ArchitectureValidationContract`: Evidence-bound validation binding proof to exact revision and environment anchors, with complete canonical proof states (`PROVEN`, `NOT_PROVEN`, `NOT_REQUIRED`, `FAILED`).
- `ProjectArchitectureGovernanceProfile`: Configurable repository governance posture and specialist delegation profiles.

### Specialist governance upgrades

Domain specialists receive formalized governance contracts and operational boundaries:
- **The Steward**: Governs product intent and capacity envelopes, preserving ranges without premature metric fabrication.
- **Clockwork**: Controls architecture complexity budgets and mandates simpler-alternative evaluation.
- **Chronicler**: Governs database migration safety and engine-aware risk profiles.
- **Conductor**: Implements architecture governance intake routing for minimal effective specialist composition.
- **The Tuner**: Governs cross-specialist contract dependencies, executing semantic invalidation and minimal specialist re-entry across declared contract edges.
- **Overseer**: Owns contract-derived validation, binding test evidence to exact revisions and environments.
- **Cipher**: Introduces tenant-security governance, enforcing trusted tenant contexts and default-deny resource boundaries without imposing multi-tenant complexity on single-tenant architectures.
- **Arbiter**: Enforces contract and evidence freshness, preventing progression on stale or unverified inputs.
- **Ponytail**: Enforces upstream-contract validation, failing closed on missing, stale, or contradictory contracts before code modification.
- **Scribe**: Integrates evidence-preserving documentation, preventing silent status promotion.
- **Governor, Weaver, Cloak, and Dagger**: Audited under OR-GOV-9 and confirmed sufficient. Dagger remains strictly gated, simulation-first, with live destructive execution permanently blocked.

### Scribe traceability and documentation

Scribe undergoes a major expansion into domain narrative modeling, requirements traceability, and documentation drift reconciliation:
- **Operating Modes**: Supports `SPEC_TO_SYSTEM`, `SYSTEM_TO_DOCS`, and `RECONCILE`.
- **Bidirectional Traceability**: Links specifications, architecture decisions, code implementations, and validation evidence.
- **Claim and Evidence Discipline**: Reconstructs as-built system documentation while preserving provenance and copyright safeguards. Scribe documents specialist decisions without replacing specialist ownership.

### Runtime architecture refoundation

The Orchestra runtime establishes a clean, bounded hexagonal architecture structure across completed AR-0, AR-1, and AR-2 milestones:
- **Bounded Packages**: Establishes `orchestra_runtime/domain/`, `orchestra_runtime/application/`, `orchestra_runtime/infrastructure/`, `orchestra_runtime/bootstrap/`, and `orchestra_runtime/shared/`.
- **Domain Extraction**: Pure domain packages own canonicalization, context, governance authority, capabilities, execution correlation, execution identity, lifecycle, and capability manifests.
- **Compatibility Facades**: Legacy public import paths are preserved via thin facades while internal modules enforce unidirectional dependency constraints.
- **Architecture Boundaries**: Machine-validated via `scripts/validation/validate_architecture_boundaries.py` to prevent flat-module sprawl and unauthorized layer coupling.

### Specialist/provider execution boundaries

Specialist execution profiles and provider interfaces are formalized:
- Standardized specialist execution requests and receipts.
- Revalidated Codex MCP `2026-07-28` integration path.
- Provider availability and model capabilities are strictly bounded; neither grants autonomous execution authority.

### Registry O7

Integration of Registry O7 query optimization:
- Governed query optimization with consumer contract and runtime state tracking.
- Conformance validation with full backward-compatibility fallback to O1-O6 query patterns.

### Cloak reference intelligence

Cloak UI Reference Corpus Intelligence (CUIR) reaches bounded adoption:
- Normalized, provenance-aware UI pattern inventory and static pattern analysis.
- Bounded progressive retrieval with project-native design requirements retaining strict precedence (`ADOPT_OPTIONAL`).

### Validation and release assurance

Expanded deterministic validation infrastructure:
- Machine-governed architecture boundary enforcement.
- 22 end-to-end integration and behavioral regression suites.
- Cross-platform validation across Ubuntu, Windows, and macOS.
- Strict CodeQL security analysis, Governance Check deterministic gates, routing contract checks, Tuner collaboration checks, and prompt-load budget tracking.

## Compatibility

- **Backward Compatibility**: Fully backward compatible with v1.7.0 configuration files, skill definitions, and CLI command structures.
- **Runtime Imports**: Legacy `orchestra_runtime` import surfaces remain functional through compatibility facades.
- **Host Adapters**: All 11 package and host surfaces are aligned at version `1.8.0`.

## Important non-promotions and known limitations

In accordance with Orchestra's evidence-bound governance policy, the following boundaries and non-promotions are explicitly documented:
- **AR-3 and AR-4 Not Included**: The runtime refoundation in v1.8.0 covers completed milestones AR-0, AR-1, and AR-2. Future phases AR-3 and AR-4 remain future work and are not authorized or included.
- **MigrationRiskContract Production Gap**: `MigrationRiskContract.production_data` remains Boolean-only; the pre-contract gap for unknown production environments remains documented and preserved.
- **Host Maturity Ceilings**: Scaffold-only host adapters remain scaffold-only and are not promoted to supported status.
- **UI Reference Intelligence**: Cloak CUIR remains optional (`ADOPT_OPTIONAL`); external references cannot override project design requirements.
- **Specialist and Provider Boundaries**: Model capabilities, MCP exposure, and provider availability do not grant autonomous mutation or execution authority.
- **Dagger Safeguards**: Dagger remains gated and simulation-first; live destructive execution remains blocked in both pass and fail paths.
- **Experimental Features**: Research prototypes and experiments without proven repeatable benefit remain unpromoted.

## Upgrade guidance

1. Update repository package configurations or host extension manifests to `1.8.0`.
2. Run `python scripts/governance_check.py --strict` to verify local repository configuration.
3. Review any project-specific architecture contracts against schemas in `machine/schemas/`.
